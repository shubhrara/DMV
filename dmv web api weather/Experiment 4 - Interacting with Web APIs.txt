EXPERIMENT 4 – INTERACTING WITH WEB APIs
Problem: Analyzing Weather Data from OpenWeatherMap API
Location: Pune, India

============================================================
1. WHAT THIS PRACTICAL DOES
============================================================

This practical gets weather forecast data for Pune from OpenWeatherMap, extracts useful fields, cleans the data, calculates statistics, creates graphs, groups readings by day, displays the location on a map, checks correlations and saves CSV files.

IMPORTANT:
- The supplied JSON contains 40 forecast records at 3-hour intervals (about five days).
- This is forecast data, NOT historical weather data.
- The notebook can run offline using the supplied JSON file.
- A personal API key is needed only to fetch fresh live data.
- The results cover one location and a short period, so they cannot support long-term seasonal conclusions.

Files in the ZIP:
- DMV_Experiment_4_Web_API_Weather_Simple.ipynb: notebook to run.

- api_key.txt: placeholder for your API key.
- Pune_Weather_Cleaned.csv and Pune_Daily_Weather_Summary.csv: output files.

3. OPTIONAL LIVE API REQUEST – CELL 4
============================================================

Code:
# Optional live API request
import requests

try:
    key = open("api_key.txt").read().strip().split("=", 1)[1]
    if key != "PASTE_YOUR_OWN_API_KEY_HERE":
        url = "https://api.openweathermap.org/data/2.5/forecast"
        params = {"q": "Pune,IN", "appid": key, "units": "metric"}
        response = requests.get(url, params=params, timeout=20)
        response.raise_for_status()
        weather = response.json()
        print("Fresh data downloaded from OpenWeatherMap.")
    else:
        raise ValueError("No API key entered")
except Exception as e:
    print("Using the supplied API response instead.")
    with open("OpenWeatherMap_Pune_API_Response.json") as f:
        weather = json.load(f)

Line-by-line:
- # starts a comment. Python ignores it; it is for people reading the code.
- import requests loads the requests library, which sends HTTP requests to websites and APIs.
- try begins a block where an error may occur. If an error happens, Python moves to except.
- open("api_key.txt") opens the key file.
- .read() reads the complete file as text.
- .strip() removes extra spaces and newline characters from the beginning and end.
- .split("=", 1) splits the text at the first equals sign into two parts.
- [1] selects the second part, which is the API key.
- if checks a condition.
- != means “not equal to”. The code checks that the placeholder has been replaced by a real key.
- url stores the OpenWeatherMap forecast API endpoint.
- params is a dictionary containing request parameters:
  - q: city and country code, Pune, India.
  - appid: the user's API key.
  - units: metric units, so temperature is in Celsius and wind speed is in metres per second.
- requests.get(url, params=params, timeout=20) sends a GET request. timeout=20 means it will wait up to 20 seconds.
- response.raise_for_status() raises an error if the server returns an unsuccessful HTTP status.
- response.json() converts the JSON response into Python dictionaries and lists.
- weather stores the API response.
- print() displays a message.
- else runs when the key is still the placeholder.
- raise ValueError(...) deliberately raises an error to activate the fallback.
- except Exception as e catches an error. e stores the error details, though this code does not print them.
- with open(...) as f opens the supplied JSON file. with automatically closes the file afterwards.
- json.load(f) reads the JSON file and converts it into Python data.

What is an API?
API means Application Programming Interface. It allows one software application to request data or services from another application. Here, our Python program requests weather information from OpenWeatherMap.

GET request:
A GET request asks a server to return information. It is used here to retrieve forecast data.

Why is there a fallback?
If there is no API key, no internet, or the request fails, the notebook loads the saved JSON response. This makes the practical usable offline.

Security:
Never share your real API key or upload it publicly. Keep api_key.txt private.

A. To handle errors without immediately stopping the program and to use the saved response if the live request fails.

4. EXTRACT WEATHER DATA – CELL 6
============================================================

Code:
rows = []
for item in weather["list"]:
    rows.append({
        "datetime": item["dt_txt"],
        "temperature": item["main"]["temp"],
        "humidity": item["main"]["humidity"],
        "wind_speed": item["wind"]["speed"],
        "rainfall": item.get("rain", {}).get("3h", 0)
    })

df = pd.DataFrame(rows)
df.head()

Line-by-line:
- rows = [] creates an empty list. We will store one dictionary per forecast record in it.
- for item in weather["list"]: loops through every forecast item in the list.
- weather["list"] accesses the list of forecast records inside the API response.
- item is the current forecast record during each loop.
- rows.append(...) adds a new dictionary to the rows list.
- A dictionary stores information as key:value pairs.
- "datetime": item["dt_txt"] extracts the date and time text.
- item["main"]["temp"] accesses the temperature inside the main section.
- item["main"]["humidity"] extracts humidity percentage.
- item["wind"]["speed"] extracts wind speed.
- item.get("rain", {}) safely accesses the rain section. If rain is absent, it returns an empty dictionary.
- .get("3h", 0) gets rainfall for the previous 3-hour period. If the key is absent, it uses 0.
- df = pd.DataFrame(rows) converts the list of dictionaries into a Pandas DataFrame (table).
- df.head() displays the first five rows by default.

Why use get() for rainfall?
Some forecast records may not contain a rain field. Direct indexing could cause a KeyError. get() provides a default value of 0 when the field is missing.

5. EXPLORE AND CLEAN THE DATA – CELL 8
============================================================

Code:
print("Shape:", df.shape)
print(df.info())
print("\\nMissing values before cleaning:")
print(df.isnull().sum())

df["datetime"] = pd.to_datetime(df["datetime"])
for col in ["temperature", "humidity", "wind_speed", "rainfall"]:
    df[col] = pd.to_numeric(df[col], errors="coerce")
    df[col] = df[col].fillna(df[col].median())

df = df.drop_duplicates().sort_values("datetime").reset_index(drop=True)
print("\\nMissing values after cleaning:", df.isnull().sum().sum())

Line-by-line:
- df.shape returns a tuple: (number of rows, number of columns).
- df.info() displays column names, data types and non-null counts.
- df.isnull() checks every cell and returns True for missing values.
- .sum() counts missing values column-wise.
- pd.to_datetime() converts the datetime column into Pandas datetime values so dates and times can be analysed properly.
- for col in [...] loops through the four numeric weather columns.
- df[col] selects the current column.
- pd.to_numeric(..., errors="coerce") converts values into numbers. Invalid values become NaN.
- NaN means Not a Number and is used to represent missing/invalid numeric data.
- .median() calculates the middle value of the column after sorting.
- .fillna(...) replaces missing values with that column's median.
- df.drop_duplicates() removes repeated rows.
- .sort_values("datetime") sorts records by date and time.
- .reset_index(drop=True) creates a fresh 0,1,2... index. drop=True prevents the old index from becoming a new column.
- df.isnull().sum().sum() counts all missing values across the whole DataFrame.
- "\\n" represents a new line in the printed message.

Why convert datetime?
Text dates are not as useful for date calculations, sorting by actual time, or extracting the date. Datetime format supports these operations.

Why use median?
The median is less affected by unusually high or low values than the mean. It is used here to fill missing numeric values.

Important detail:
The code fills missing numeric values with the median of each column. It does not fill missing datetime values. Also, rainfall missing from the original API record was already assigned 0 during extraction.

Viva:
Q. What is data cleaning?
A. Finding and handling missing, invalid, duplicate or inconsistent data.

Q. What does shape return?
A. A pair containing row count and column count.

Q. What is NaN?
A. A marker used for missing or invalid numeric values.

Q. Mean vs median?
A. Mean is the sum divided by the count. Median is the middle value after sorting. Median is generally less affected by outliers.

Q. What does errors="coerce" do?
A. Invalid values are converted to NaN instead of causing a conversion error.

Q. Why drop duplicates?
A. To avoid counting the same record more than once.

Q. Why reset the index?
A. To give the cleaned, sorted DataFrame a fresh continuous index.

8. DAILY AGGREGATION – CELL 14
============================================================

Code:
df["date"] = df["datetime"].dt.date
daily = df.groupby("date").agg(
    avg_temperature=("temperature", "mean"),
    max_temperature=("temperature", "max"),
    avg_humidity=("humidity", "mean"),
    total_rainfall=("rainfall", "sum")
).reset_index()

display(daily.round(2))
daily.plot(x="date", y="avg_temperature", kind="bar",
           title="Daily Average Temperature", legend=False, figsize=(8, 4))
plt.ylabel("Temperature (°C)")
plt.tight_layout()
plt.show()

Line-by-line:
- df["datetime"].dt accesses datetime-specific properties and methods.
- .date extracts only the date and removes the time part.
- df["date"] = ... creates a new date column.
- df.groupby("date") groups all records belonging to the same date.
- .agg() calculates multiple summary values for each group.
- avg_temperature=("temperature", "mean") calculates the mean temperature per date.
- max_temperature=("temperature", "max") calculates the highest temperature per date.
- avg_humidity=("humidity", "mean") calculates average humidity per date.
- total_rainfall=("rainfall", "sum") adds rainfall values per date.
- .reset_index() turns the grouped date index back into a normal column.
- display(daily.round(2)) displays the daily table rounded to two decimal places.
- daily.plot(...) plots daily average temperature as a bar chart.
- legend=False hides the legend because only one column is plotted.
- figsize=(8, 4) sets the graph dimensions.
- Remaining Matplotlib commands label, arrange and display the graph.

What is aggregation?
Aggregation means combining multiple records into a summary, such as calculating the average temperature for each day.

Why group by date?
The original data has readings every three hours. Grouping by date combines the readings for the same day into daily summaries.

Viva:

10. CORRELATION BETWEEN WEATHER ATTRIBUTES – CELL 18
============================================================

Code:
corr = df[["temperature", "humidity", "wind_speed", "rainfall"]].corr()
plt.imshow(corr, cmap="coolwarm", vmin=-1, vmax=1)
plt.colorbar(label="Correlation")
plt.xticks(range(4), corr.columns, rotation=30)
plt.yticks(range(4), corr.columns)
plt.title("Weather Attribute Correlation")
for i in range(4):
    for j in range(4):
        plt.text(j, i, round(corr.iloc[i, j], 2), ha="center", va="center")
plt.tight_layout()
plt.show()

Line-by-line:
- df[[...]] selects the four weather columns. Double square brackets are used to select multiple columns.
- .corr() calculates pairwise correlation between the selected numeric columns. By default, Pandas uses Pearson correlation.
- corr stores the resulting correlation matrix.
- plt.imshow(corr, ...) displays the matrix as a coloured image (heatmap-like display).
- cmap="coolwarm" selects the colour map.
- vmin=-1 and vmax=1 set the colour scale limits because correlation ranges from -1 to +1.
- plt.colorbar() displays the colour scale.
- plt.xticks(range(4), corr.columns, rotation=30) labels the four x-axis positions with column names and rotates them 30 degrees.
- plt.yticks(...) does the same for the y-axis.
- plt.title() adds the chart title.
- for i in range(4) loops through row positions 0 to 3.
- for j in range(4) loops through column positions 0 to 3.
- corr.iloc[i, j] accesses the value at row i and column j using integer positions.
- plt.text(j, i, ...) writes the rounded correlation value inside the corresponding cell.
- ha="center" horizontally centres the text.
- va="center" vertically centres the text.
- plt.tight_layout() adjusts spacing.
- plt.show() displays the chart.

How to interpret correlation:
- +1: perfect positive linear relationship.
- 0: no linear relationship.
- -1: perfect negative linear relationship.
- Positive: when one variable increases, the other tends to increase.
- Negative: when one increases, the other tends to decrease.
- Correlation does NOT prove causation.

Viva:
Q. What is correlation?
A. A measure of the strength and direction of the relationship between two variables.

Q. What is a correlation matrix?
A. A table showing correlation values for every pair of selected variables.

Q. What does iloc do?
A. Selects rows and columns by integer position.

Q. Why are the scale limits -1 and +1?
A. Because correlation coefficients lie between -1 and +1.

Q. Does correlation mean causation?
A. No. Correlation alone does not prove that one variable causes another.

Q. What is the diagonal of a correlation matrix?
A. It contains 1.0 because each variable is perfectly correlated with itself.
